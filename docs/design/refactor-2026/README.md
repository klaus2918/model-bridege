## 1. 为什么重构

当前不是"功能不够"，而是"接入对象太多、每类对象一套说法"：

| 现状 | 具体表现 | 用户成本 |
|---|---|---|
| 入口多 | 概览、模型、配置、用量、提示词、免费来源、ZCode、日志 8 个页签 | 不知道"加一个上游"该去哪 |
| 表单长 | 配置页的上游卡片同时暴露协议、地址、密钥来源、逐模型密钥、compat、模型覆盖、会话头等 20+ 字段 | 官方厂商也要面对一堆高级选项 |
| 来源多 | 官方预设、自定义上游、免费来源、ZCode 账号池、插件，各有一套接入动作 | 状态分散、无法统一启停与排障 |
| API 多 | `/api/...` 40+ 个端点，AI 无法判断该调哪个 | 内置 AI 难以安全地协助配置 |
| 凭据散 | 环境变量、凭据文件、DPAPI 密钥库、逐模型密钥、ZCode 账号表 | 没有统一的"这把 key 还能不能用"视图 |
| 页面杂 | 概览同时承担 KPI、上游表、接入信息、本地路径；表格与卡片重复 | 首屏信息噪声大，重点不突出 |

## 2. 重构目标

1. **一个接入对象**：无论官方、自定义、免费源、账号池还是插件，最终都归一为 `Upstream`，共用一条装配、校验、路由、观测链路。
2. **两条配置路径**：官方厂商只填 Key；自定义厂商只填「标识、厂商、地址、协议、Key」五项，其余有默认值。
3. **模板即默认值**：模板声明协议、地址、鉴权、隐私、能力、模型目录；选择模板后只补空字段。
4. **凭据池一等公民**：插件可声明 `auth.mode=pool`，统一管理多账号/多 Key、轮换、冷却、配额与故障转移。
5. **AI 可安全配置**：提供机器可读目录、Schema、脱敏快照、dry-run 计划与受控应用；密钥/账号永不经过 AI 接口。
6. **页面收敛**：一级导航从 8 个降为 7 个，按「工作台 / 接入 / 资源 / 观测 / 设置」分组；首屏只回答"网关是否健康、哪个接入有问题、下一步做什么"。

## 3. 六条不可破坏的兼容约束

| # | 约束 | 落地方式 |
|---|---|---|
| C1 | `bridge.config.json` 仍是唯一事实源 | 新能力以**可选字段**写入；未知字段保留；`merge_incoming` 语义不变 |
| C2 | 旧调用方式全部继续可用 | `/v1`、`/{upstream}/v1`、`/unified/v1`、`/unified/{group}/v1`、`/v1/models` 原样保留 |
| C3 | SQLite 只增不删 | 新表只进 `SCHEMA` 的 `CREATE TABLE IF NOT EXISTS`；不加破坏性 `MIGRATIONS` |
| C4 | 旧配置无需迁移即可启动 | `version` 缺省视为 v1；所有新字段可缺省；旧 exe 读新配置忽略未知字段 |
| C5 | 明文密钥仍不作为凭据 | 继续只认 env / file / store 引用；新增池成员也只存 secret 引用 |
| C6 | 插件安装/卸载不执行 DDL、不直接写配置 | 安装只写 `plugins` 两行；接入必须经 `attach`，由内核备份、原子写、回读 |

## 4. 核心设计决策（需要你确认）

| 编号 | 决策 | 备选 |
|---|---|---|
| D1 | 物理存储不变，新增"接入视图"聚合层（后端 `AccessObject`），不引入第二份配置 | 新建 `access.json`（否决：双事实源） |
| D2 | 凭据池新增两张内核表 `credential_pools` / `credential_members`，ZCode 旧表保留并适配为 legacy 池 | 复用 `plugin_kv`（否决：无法约束引用完整性） |
| D3 | 池默认策略 `priority`（按优先级取第一个可用），可选 round_robin / weighted / least_used | 默认轮询（否决：免费源与付费源混用会不可预期） |
| D4 | AI 配置接口默认**只读 + 草案**；应用变更必须带人工确认令牌；敏感字段禁止经 AI 写入 | AI 可直接写（否决：密钥泄露面过大） |
| D5 | 一级功能域收敛为 7 个：总览、接入、凭据、插件、流量、观测、设置；侧栏按 5 个分区展示，接入域含 3 个子页 | 保留 8 个页签（否决：模型/日志应降为子视图） |
| D6 | 官方模板默认勾选隐私保护（ZDR），并按厂商能力显示"请求级/账户级/不支持" | 全局强制 ZDR（否决：部分厂商无请求级开关） |
| D7 | 快速添加官方厂商 = 选模板 → 填 Key → 完成（2 步） | 仍走完整表单（否决：不满足"只填 Key"） |
| D8 | 自定义厂商最少 5 项：标识、厂商、请求地址、协议、Key | 增加必填模型（否决：可自动拉取） |

## 7. 本轮需要你确认的 10 个点

1. 一级功能域是否按 D5 收敛为 7 个（侧栏 5 个分区，接入域含全部接入/模型目录/路由组 3 个子页）？
2. 官方厂商"只填 Key"是否接受自动写入本机加密库（DPAPI），而不是环境变量？
3. 自定义厂商 5 个必填项是否足够（模型目录自动拉取，失败则手填）？
4. 凭据池默认策略是否用 `priority`，以及是否允许同一上游同时绑定"单 Key + 池"？
5. 池成员失败后的冷却时间默认 60s、连续失败 3 次熔断，是否合适？
6. AI 配置接口是否坚持"只读 + 草案 + 人工确认应用"？
7. AI 是否可以读取脱敏后的池统计（数量/可用/冷却），但不读取成员标签？
8. 是否保留"配置页原始 JSON 编辑"作为高级入口（默认折叠）？
9. 旧 ZCode 账号页是否收进"凭据 → 账号池"子视图，不再单独占一级页签？
10. 视觉方向是否接受"深墨绿控制台 + 信号绿强调 + 暖米白浅色主题"（见原型）？

> 确认方式：直接回复编号与结论；未确认项按本文默认值执行。
